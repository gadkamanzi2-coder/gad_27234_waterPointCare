# WaterPointCare Rwanda — Logical Data Dictionary

## 1. Introduction

This document describes the entities, columns, keys and relationships in the logical database design for WaterPointCare Rwanda.

The database is designed to organize water-point information, record assessments, manage fault reports, assign maintenance teams, track repair jobs and maintain a history of status changes.

This is a logical data dictionary. Oracle-specific data types and column sizes will be defined during Phase IV.

---

## 2. Entity 1: WATER_POINTS

**Purpose:** Stores the identification, geographical location and basic characteristics of each physical water point.

**Primary Key:** `water_point_id`

| Column | Key | Required? | Unique? | Description |
|---|---|---|---|---|
| water_point_id | PK | Yes | Yes | Unique identifier for a water point, based on the source dataset's Unique ID. |
| latitude | — | Yes | No | Geographic latitude of the water point. |
| longitude | — | Yes | No | Geographic longitude of the water point. |
| geo_level_1 | — | No | No | First administrative geographical level from the source dataset. |
| geo_level_2 | — | Yes | No | District or equivalent administrative area. |
| geo_level_3 | — | No | No | Third geographical administrative level. |
| geo_level_4 | — | No | No | Fourth geographical administrative level. |
| geo_level_5 | — | No | No | Fifth geographical administrative level. |
| improved_technology | — | No | No | Improved water-point technology recorded in the source dataset. |
| unimproved_technology | — | No | No | Unimproved water-point technology, where applicable. |
| system_type | — | Yes | No | Indicates whether the water system is a piped system or a handpump. |

**Design note:** The source dataset provides the water-point identifier, location and technology information. These attributes form the initial water-point profile. Future assessments will be stored separately.

## 3. Entity 2: WATER_POINT_ASSESSMENTS

**Purpose:** Stores inspection and assessment observations for water points. A water point can have multiple assessments over time.

**Primary Key:** `assessment_id`

**Foreign Key:** `water_point_id` references `WATER_POINTS(water_point_id)`.

| Column | Key | Required? | Unique? | Description |
|---|---|---|---|---|
| assessment_id | PK | Yes | Yes | Unique identifier for each assessment, generated by the database. |
| water_point_id | FK | Yes | No | Identifies the water point being assessed. |
| assessment_date | — | Yes | No | Date on which the water-point assessment was conducted. |
| level_of_service_score | — | No | No | Numerical score representing the water point's level of service. |
| level_of_service | — | No | No | Classification of the level of service, such as High, Intermediate, Basic or Inadequate. |
| has_improved_water_point | — | No | No | Indicates whether the water point qualifies as an improved water point. |
| is_functional | — | No | No | Indicates whether the water point is functional according to the source assessment. |
| is_source_protected | — | No | No | Indicates whether the water source is protected. |
| number_of_users | — | No | No | Number of people reported to use the water point. |
| users_meet_standard | — | No | No | Indicates whether the number of users meets the applicable standard. |
| is_out_of_service_or_broken | — | No | No | Indicates whether the water point or system is broken or out of service. |
| breakage_frequency_meets_standard | — | No | No | Indicates whether the reported frequency of breakdowns meets the standard. |
| breakage_duration_meets_standard | — | No | No | Indicates whether the reported number of days broken meets the standard. |
| monthly_outage_meets_standard | — | No | No | Indicates whether the monthly outage duration meets the standard. |
| water_available_on_visit | — | No | No | Indicates whether water was available on the day of the assessment. |
| seconds_to_fill_20_litres | — | No | No | Time in seconds required to fill a 20-litre container. |
| handpump_flow_rate | — | No | No | Flow rate in litres per second for handpump systems. |
| piped_litres_per_person_per_day | — | No | No | Daily water quantity available per person for piped systems. |
| quantity_meets_standard | — | No | No | Indicates whether the available water quantity meets the standard. |
| ecoli_meets_standard | — | No | No | Indicates whether the E. coli measurement meets the required standard. |
| residual_chlorine_meets_standard | — | No | No | Indicates whether residual chlorine meets the required standard. |
| bacteria_meets_standard | — | No | No | Indicates whether bacteria measurements meet the required standard. |
| other_contaminant_present | — | No | No | Records whether another contaminant of concern was identified. |
| other_contaminant_meets_standard | — | No | No | Indicates whether the other identified contaminant meets the required standard. |
| water_quality_meets_standard | — | No | No | Overall result indicating whether water quality meets the applicable standards. |
| overall_condition_is_good | — | No | No | Indicates whether the water point or system is in good overall condition and functioning. |

**Design notes:**

1. Each assessment receives its own `assessment_id`; the source `Instance Id` is not used as a separate assessment identifier because it duplicates `Unique ID` in the complete source records.
2. `water_point_id` connects every assessment to the physical water point.
3. Assessment measurements and results are stored here because they describe the condition observed during an inspection.
4. Some fields are optional because the source dataset contains missing or technology-specific values. Their actual validity and cleaning rules will be handled during Phase IV.
5. The assessment date and other source values must be cleaned and converted to suitable Oracle types during Phase IV.

## 4. Relationship between the first two entities

- One `WATER_POINTS` record can have zero or many `WATER_POINT_ASSESSMENTS` records.
- Each `WATER_POINT_ASSESSMENTS` record must belong to exactly one `WATER_POINTS` record.

This is a one-to-many relationship.

## 9. Entity 7: REPAIR_PART_USAGE

**Purpose:** Records the spare parts used during repair jobs. This entity connects repair jobs with spare parts and resolves the many-to-many relationship between them.

| Column | Meaning | Key | Required? | Unique? |
|---|---|---|---|---|
| repair_job_id | Identifies the repair job that used the part | PK, FK | Yes | Part of composite PK |
| part_id | Identifies the spare part used | PK, FK | Yes | Part of composite PK |
| quantity_used | Number of units of the spare part used | — | Yes | No |
| unit_cost_at_use | Cost per unit when the part was used | — | Yes | No |

**Primary key:** The combination of `repair_job_id` and `part_id` forms a composite primary key.

**Relationship:** One repair job can use zero or many spare parts. One spare part can be used in zero or many repair jobs. Each record in this entity must refer to exactly one repair job and one spare part.

## Phase IV — Oracle Physical Data Dictionary

### 1. WATER_POINTS

**Purpose:** Stores the identity and geographical location of each physical water point. Each water point is identified using the original dataset's `Unique ID`.

**Design justification:** The table separates permanent water-point identity and location from historical inspection measurements, which are stored in `WATER_POINT_ASSESSMENTS`. The natural primary key is retained because the source provides a unique identifier for each valid water point.

| Column | Oracle data type | NULL? | Constraint | Description / reason |
|---|---|---|---|---|
| water_point_id | VARCHAR2(100) | NOT NULL | PK | Unique identifier from the source dataset. |
| latitude | NUMBER(10,7) | NULL | CHECK (-90 to 90) | Geographic latitude of the water point. |
| longitude | NUMBER(10,7) | NULL | CHECK (-180 to 180) | Geographic longitude of the water point. |
| elevation | NUMBER(8,2) | NULL | — | Elevation recorded for the water point. |
| geo_level_1 | VARCHAR2(100) | NULL | — | First geographical administrative level. |
| geo_level_2 | VARCHAR2(100) | NULL | — | Second geographical administrative level. |
| geo_level_3 | VARCHAR2(100) | NULL | — | Third geographical administrative level. |
| geo_level_4 | VARCHAR2(100) | NULL | — | Fourth geographical administrative level. |
| geo_level_5 | VARCHAR2(100) | NULL | — | Fifth geographical administrative level. |
| geo_level_6 | VARCHAR2(100) | NULL | — | Sixth geographical administrative level. |
| geo_level_7 | VARCHAR2(100) | NULL | — | Seventh geographical administrative level. |

**Primary key:** `water_point_id`

**Check constraints:**
- `ck_water_points_latitude`: latitude must be between -90 and 90 when provided.
- `ck_water_points_longitude`: longitude must be between -180 and 180 when provided.

**Tablespace:** `WATERPOINTCARE_DATA`

**Normalization:** The table stores one record per water point. Inspection measurements and maintenance events are stored separately to support multiple assessments and fault reports for the same water point.
